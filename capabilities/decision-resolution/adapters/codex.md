## Codex Provider Adapter

1. This Capability is interactive-only. Confirm that the current user is actively participating in this repository session. If invoked headlessly, autonomously, from a schedule, cron, background process, batch, CI, webhook, or without a current user response, refuse immediately before reading Decision Items, loading the database, calling a provider, or writing anything. A default recommendation, plan, or inferred intent is not user judgment.
2. Use the repository command runner from the Trade Journal root to read unresolved packets with `npx tsx scripts/ops/list-decisions.ts --json`. Optionally read `npx tsx scripts/ops/maintenance-status.ts --json` only to distinguish agent maintenance work from already-raised Decision Items. Do not drain maintenance or create a new packet in this Capability.
3. Present one exact unresolved packet at a time: decision ID and type, subject, why it was raised, material evidence, bounded `recommended_actions`, and any `default_recommendation`. Ask the current user to select the exact action. Refuse silence, ambiguity, unsupported wording, model inference, a prior unrelated preference, or a timeout/default as missing judgment; do not continue to any write.
4. For a built-in mechanical action, preview and then apply only with `npx tsx scripts/ops/resolve-decision.ts --id <decision-id> --action <selected-action> <required-target-ids> --by user`. For a delegated action, complete the packet's exact runbook first, capture the actual write records, and close only with `scripts/ops/resolve-decision.ts --by user --notes <rationale> --writes <exact-json>`. Never directly edit `journal_entries` or a graph table.
5. If the selected resolution requires status mutation, first run `npx tsx scripts/ops/update-entity-status.ts --entity-type <type> --id <uuid> --status <status> --rationale <user-approved-rationale>`. Continue to `resolve-decision.ts --by user` only after that validated transition and its audit succeed. An invalid or failed transition leaves the Decision Item unresolved.
6. Report sandbox or network denial, missing database access, an unknown or inactive Decision Item, missing target data, a malformed write record, an invalid transition, or audit failure as refused, unavailable, or failed. Return the exact Decision Item ID, the user's selected action, resolution status, approved operation results, any validated transition, exact writes, `decision_resolved` audit outcome, and remaining unresolved count without partial-success language.

Only `scripts/ops/resolve-decision.ts --by user` may close the selected Decision Item. Only `scripts/ops/update-entity-status.ts` may perform a status-changing resolution. The adapter has no ad-hoc SQL, Supabase MCP write, generic database, Decision Item production, maintenance-draining, scheduler, credential, order, trade, execution, or provider-installation authority. It must never be declared unattended-current, scheduled, or eligible for headless execution.
