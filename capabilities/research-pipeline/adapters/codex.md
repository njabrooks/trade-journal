## Codex Provider Adapter

1. Require one explicit Trade Journal research insight UUID. From the Trade Journal root, use Codex's repository command runner with `npx tsx scripts/research-pipeline.ts`. Build independently invocable zero-write results through `--pipeline-status`, `--idea-intake`, `--thesis-formalization`, `--unknown-mapping`, `--research-preparation`, `--unknown-research`, `--evidence-synthesis`, `--thesis-expression`, `--gate-decision`, or `--graduation` with `<file|->`; validate stage bytes through `--validate-stage-result`. Use `--describe`, `--evaluate`, and `--validate-result` for the aggregate.
2. Preserve authority exactly. Notes/Tana owns capture, source material, and Toulmin extraction. Trade Journal owns promoted claims, publication state, governed relationships, theses, unresolved Decision Items, and journal audit. All ten stage results and the aggregate coordinate only and write nothing.
3. Preserve exact source insight, source claim, content digest, evidence, reasoning, backing, qualifier, every rebuttal, time horizon, source URLs, contradictions, ambiguity, digest-bound user judgment audit, and prior-stage digest. Reuse provenance-bearing claims. Holdings, tickers, keywords, and provider recommendations are never semantic proof of claim identity or thesis bearing.
4. Preserve the four accepted 1.1.0 intake/formalization seams unchanged: supplied-only pipeline status, audited user idea selection and classification, falsifiable formalization with its exact failure-mode rules and user gate, and user-advanced unknown mapping with decisive-unknown, resolvability, priced-in, kill-condition, and research-payoff rules.
5. `research_preparation` produces a portable provider-neutral brief from the exact accepted thesis, unknown, and research track. Do not require Claude Desktop, a connector, or a provider-specific citation surface. `unknown_research` requires explicit HTTPS citations and at least two independent source domains; if browsing, credentials, or source access is unavailable, report `unavailable` rather than fabricating evidence. Permit at most one result for each exact `(unknownId, track)` pair while allowing distinct falsification, validation, and analogue tracks for the same unknown.
6. `evidence_synthesis` binds every supplied track-result digest, covers every mapped unknown at least once, retains unresolved contradictions, and derives advance, hold, kill, or modify from posterior confidence, kill conditions, core-mechanism support, and decision-critical gaps. It does not update a file, confidence record, database entity, status, signal, or Decision Item.
7. `thesis_expression` requires an audited user decision to enter Stage 5 and returns value-chain analysis, candidates, expression-failure risk, entry/exit/review criteria, and sizing inputs without a position size, quantity, allocation, order, or trade instruction. `gate_decision` remains `judgment_required` until the user records act, watch, or discard and may preserve an explicit user override.
8. `graduation` is a provenance-bound handoff plan only. Bind claim identity and any existing main-claim reuse to the exact validated Registry-locked claims-synthesis context and result; route later persistence through Registry-locked research-publication and belief-research-relation; use Registry-locked thesis-underwriting for articulation with rebuttal-derived resolution. Return `judgment_required` until the user accepts the exact handoff and claims binding by its boundary digest; preserve an explicit decline as `refused`. A proposed thesis starts at `developing`; `monitoring` remains expression-cascade derived. Do not invoke a recorder, create or update an entity, configure a signal, or mutate status.
9. Every stage returns `execution: { mode: "stage_result_only", writes: [] }`. Compose stage results through their public validators and exact digest chain. Resolve governed dependencies through the published Registry Lock without copying or loosening their contracts. The aggregate remains `execution: { mode: "aggregate_coordination_only", writes: [] }`.
10. Report each aggregate stage as `incomplete`, `unavailable`, `stale`, `refused`, `failed`, `judgment_required`, or `ready`. Retry only canonically identical input using its digest. Missing or unavailable external prerequisites are never a partial success.
11. All ten legacy entry points remain active, unchanged, and rollback-capable during coexistence. Do not modify `.claude` or `.agents` discovery, remove legacy inputs, create tombstones, or begin issue #69 contraction.
12. If the exact research-publication stage returns `judgment_required`, the only named persistence operation is `scripts/ops/publish-research.ts --stdin`. If belief-research-relation returns its recording judgment boundary, the only named operation is `scripts/ops/record-belief-research-relation.ts --stdin`. Never invoke either from aggregate or stage authority.
13. This adapter must not use ad-hoc SQL, Supabase MCP writes, direct API mutation, generic writes, schedulers, credentials, provider discovery, or production-data evidence; must not change status, resolve a Decision Item, configure signals, mutate a strategy or position, or place or stage an order or trade.
14. Unattended execution is conditional only for read-only status, portable preparation, validation of explicitly supplied evidence, and aggregate describe, evaluate, and validation. Provider research may run only with declared source access and honest unavailable behavior. Idea selection, classification, every user gate, graduation acceptance, every legacy persistence path, and every accepted write remain interactive and ineligible.
