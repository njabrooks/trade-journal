## Codex Provider Adapter

1. Require one explicit Trade Journal research insight UUID. From the Trade Journal root, use Codex's repository command runner with `npx tsx scripts/research-pipeline.ts`. Build independently invocable zero-write results through `--pipeline-status`, `--idea-intake`, `--thesis-formalization`, or `--unknown-mapping` with `<file|->`; validate stage bytes through `--validate-stage-result`. Use `--describe`, `--evaluate`, and `--validate-result` for the aggregate.
2. Preserve authority exactly. Notes/Tana owns capture, source material, and Toulmin extraction. Trade Journal owns promoted claims, publication state, governed relationships, theses, unresolved Decision Items, and journal audit. These four stage results and the aggregate coordinate only and write nothing.
3. Preserve exact source insight, source claim, content digest, evidence, reasoning, backing, qualifier, every rebuttal, time horizon, ambiguity, digest-bound user judgment audit (decision ID, actor ID, recorded-at time), and prior-stage digest. Reuse provenance-bearing claims. Holdings, tickers, keywords, and provider recommendations are never semantic proof of claim identity or thesis bearing.
4. `pipeline_status` reads only explicitly supplied coordination records. `idea_intake` requires explicit audited user selection and thesis classification. `thesis_formalization` requires a falsifiable thesis, exactly five failure modes including at least two structural and one execution mode, and an exact audited user gate decision before `ready`. `unknown_mapping` may follow only an explicit user `advance`; it assesses decisive unknowns, resolvability, priced-in state, clear kill conditions, and research-payoff asymmetry, then requires an exact audited user gate decision before `ready`.
5. Every #67 stage returns `execution: { mode: "stage_result_only", writes: [] }`. It must not create a directory or stage file, write a database or journal row, change status, create or resolve a Decision Item, publish a claim or relationship, or mutate a thesis, signal, strategy, position, order, or trade.
6. Compose these stage results through their public validator and exact digest chain. Resolve Registry-locked `claims-synthesis`, `research-publication`, and `belief-research-relation` through their existing validators. Never copy or loosen stage semantics, mutation rules, or authorization boundaries inside the aggregate.
7. Report each aggregate stage as `incomplete`, `unavailable`, `stale`, `refused`, `failed`, `judgment_required`, or `ready`. The aggregate remains `execution: { mode: "aggregate_coordination_only", writes: [] }` and retries only canonically identical input using its digest.
8. Legacy `pipeline-status`, `stage-1-init-idea`, `stage-2-formalize-thesis`, and `stage-3-map-unknowns` persistence entry points remain active, unchanged, and rollback-capable. Their governed adapters add zero-write result boundaries; they do not replace persistence or active discovery.
9. `stage-4a-prep-desktop-research`, `stage-4a-research-unknown`, `stage-4b-synthesize-evidence`, `stage-5-express-thesis`, `advance-or-kill`, and `graduate-pipeline-idea` remain explicitly unmigrated for issue #68. Do not begin or reinterpret them.
10. If the exact research-publication stage returns `judgment_required`, the only named persistence operation is `scripts/ops/publish-research.ts --stdin`. If belief-research-relation returns its recording judgment boundary, the only named operation is `scripts/ops/record-belief-research-relation.ts --stdin`. Never invoke either from aggregate authority.
11. This adapter must not use ad-hoc SQL, Supabase MCP writes, direct API mutation, generic writes, schedulers, credentials, provider discovery, or production-data evidence; must not change status, resolve a Decision Item, mutate a strategy or position, or place or stage a trade.
12. Unattended execution is conditional only for read-only pipeline status and aggregate describe, evaluate, and validation with exact supplied input. Idea selection, classification, formalization gates, unknown-map gates, every legacy persistence path, and every accepted write remain interactive and ineligible.
