## Codex Provider Adapter

1. This Capability is interactive-only. Confirm that the current user is actively participating in this repository session. If invoked headlessly, autonomously, from a schedule, cron, background process, batch, CI, webhook, timeout, or without a current user response, refuse immediately before reading thesis or repository state, loading the database, calling a provider, asking a follow-up question, or writing anything. Do not create a task, schedule, or deferred continuation for the request.
2. Require one explicit verb (`query`, `what-changed`, `observe`, `assess-evidence`, or `re-underwrite`) and one explicit macro or asset thesis. Use the repository command runner from the Trade Journal root to resolve a supplied ticker, title, or ID through `npx tsx scripts/ops/thesis-snapshot.ts`; when the selector is absent, unknown, or ambiguous, return the error or candidates and obtain the user's exact target before invoking a dependency or writing.
3. Resolve `capability:scope:trade-journal/thesis-observation`, `capability:scope:trade-journal/thesis-underwriting`, and `capability:scope:trade-journal/belief-evidence-assessment` through the published Registry Lock and use their exact Codex adapters. Do not substitute the machine-local bridge, a Claude adapter, a legacy skill body, or copied dependency prose, and do not widen a dependency contract.
4. For `query`, answer conversationally from the selected snapshot's living underwriting, conviction history, active auto-derived signals, provenance-bearing claims and observations, signal-quality context, strategies, performance, and allocation. For `what-changed`, bind the latest articulation ID from that snapshot (or `none`) and invoke `npx tsx scripts/ops/thesis-delta.ts --id <uuid> --type <asset|macro> --expected-articulation-id <uuid|none>`. Use its provenance-bearing newly-created/newly-linked claim classification and post-baseline observation or assessment evidence. Treat a null baseline as unbaselined and an articulation mismatch as stale; do not substitute ad-hoc SQL. Both verbs are read-only.
5. For `observe`, pass only the exact thesis and explicit as-of time to the governed thesis-observation adapter. Preserve its Tier-1 monitoring and active-signal eligibility, current attributable source requirements, collector deferral, thesis-centric polarity, sensing-only writes, and honest unavailability. For supplied evidence, use the governed belief-evidence-assessment adapter; recording is off unless the current user explicitly requests it.
6. For `re-underwrite`, require the current user's explicit request for the exact thesis. Load the complete snapshot, refuse while `thin.unlinkedClaimCount` is non-zero or provenance, candidate-signal dispositions, signal-quality inputs, or target identity are incomplete, and explain that a new version supersedes the current resolution set. Obtain any remaining scope or disposition judgment, then delegate only to the governed thesis-underwriting adapter and its previewed bounded write path.
7. Report sandbox or network denial, unavailable database or provider access, unknown or ambiguous target, missing input or judgment, stale dependency target, or non-zero command result as refused, unavailable, stale, or failed. Return the thesis ID and type, verb, baseline, dependency calls, sources, summary, limitations, user judgments received, recording disposition, and exact writes without partial-success language.

This adapter has no direct database authority. Its maximum writes are the exact writes returned by one selected governed dependency. It must not drain maintenance, create or resolve Decision Items, change entity status, configure manual signals or `explicit_details`, create claims, alter claim-thesis links, use ad-hoc SQL, Supabase MCP writes, or generic writers, size or place trades, access credentials for convenience, install a provider, or create or change a schedule or launchd definition. It must never be declared unattended-current or eligible for headless or scheduled execution.
