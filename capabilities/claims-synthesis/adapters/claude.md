## Claude Provider Adapter

1. Require one explicit Trade Journal research insight ID. From the repository root, use the repository command runner for `npx tsx scripts/claims-synthesis.ts --prepare --insight-id <uuid>`. Continue only when it returns `status: ready`; otherwise return the exact unavailable result. Bind all work to the returned `contextDigest` computed from the full context.
2. Preserve the authority split exactly: Notes/Tana owns capture, source material, and Toulmin extraction; Trade Journal owns promoted investment entities and governed relationships. The source artifact must prove Notes/Tana provenance. Do not recreate Notes capture or treat the provider as source authority.
3. Keep all four concepts distinct in the result: `sourceEvidence` identifies Notes-owned evidence; `existingMainClaims` identifies reused Trade Journal claims; `synthesizedInvestmentClaims` contains only materially distinct proposed investment assertions; and `thesisMappings` contains only proposed governed relationships. Do not collapse these collections or describe a recommendation as a completed write.
4. Exact `(sourceInsightId, sourceClaimId)` provenance is deterministic identity. Return `reuse_exact_provenance` with the exact existing `main_claims.id`, regardless of that claim's lifecycle status. Never synthesize a duplicate of that Notes-owned source claim. For a genuinely distinct synthesis, retain `sourceClaimId`, the exact source qualifier, every source rebuttal, and a concrete synthesis rationale.
5. Assess direct semantic bearing against the full eligible macro and asset thesis catalog, including both developing and monitoring theses. Ticker and keyword overlap are retrieval hints only; they do not prove claim identity, relationship, direction, or thesis bearing. Every ambiguity must name exactly one `axis`: use `claim_identity` for uncertain identity or distinction, with no reused or synthesized resolution; use `thesis_mapping` for uncertain relationship, direction, or thesis bearing, which may retain a deterministic claim resolution but must return no thesis mapping. In either case return `defer_ambiguous`.
6. Return the exact version `1.0.0` result shape: every source claim exactly once in `sourceEvidence`; deterministic exact-provenance reuse; at most 25 synthesized claims; at most 25 ambiguities; at most 25 recommendations; and at most 5 proposed thesis mappings per source claim. Use only `supports`, `refutes`, or `foundation`, and only `high`, `medium`, or `low` confidence. Set `execution` exactly to `{ "mode": "recommendation_only", "writes": [] }` and state material limitations.
7. Save the proposed JSON only to a temporary or explicitly requested local file, then use the repository command runner for `npx tsx scripts/claims-synthesis.ts --validate-result <file|-> --context <prepared-context-file>`. A stale digest, unknown source/claim/thesis reference, missing provenance reuse, lost qualifier or rebuttal, ambiguous mapping, malformed or oversized result, unavailable input, provider failure, or validation refusal is a complete failed or unavailable outcome. Do not partially accept it or infer missing state.
8. This adapter is recommendation-only. It must not invoke `scripts/ops/create-claim.ts`, `scripts/ops/batch-create-claims.ts`, `scripts/ops/link-claim-to-thesis.ts`, `scripts/relate-research.ts` apply modes, `scripts/ops/update-entity-status.ts`, or `scripts/ops/resolve-decision.ts`; must not use ad-hoc SQL, Supabase MCP writes, or direct API mutation; must not promote, create, link, or mutate claims; and has no thesis/status, signal, Decision Item, strategy, position, or trade authority. Unattended use is eligible only under this same zero-write boundary and must preserve genuine ambiguity rather than guessing.
