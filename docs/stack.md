## 1. Purpose

This document defines the specific tools, frameworks, and libraries used to implement the Trade Journal app, along with the rationale for each choice.

---

## 2. Core Stack

### 2.1 Framework

- **Next.js (App Router)**
  - Full-stack TypeScript.
  - Server Components for data-heavy views.
  - Built-in routing and API route handlers.

### 2.2 Language

- **TypeScript**
  - Strong typing for complex financial domain models.
  - Safer refactors as the app evolves.

### 2.3 Database & Backend

- **Database**: Supabase (Postgres)
- **Schema management**: Supabase MCP (Model Context Protocol)
  - All migrations, schema changes, and database administration via MCP
  - Type generation via MCP (imported into runtime code)
  - Edge function deployment and branch management
- **Runtime queries**: Drizzle ORM (with Supabase/Postgres adapter)
  - Type-safe queries from Server Components and API routes
  - Uses types generated by MCP for full type safety
  - Alternative: Supabase client (`@supabase/supabase-js`) for simpler cases
- **Auth**: Supabase Auth (email-based, single tenant initially).

Rationale:

- Postgres is a natural fit for relational financial data.
- Supabase provides managed infra, auth, storage, and convenient local dev.
- **MCP handles schema/admin**: migrations, type generation, database management
- **Drizzle handles runtime**: type-safe queries from application code
- Clear separation: MCP for dev/admin, Drizzle for runtime queries

### 2.4 Styling & UI

- **Tailwind CSS**
  - Utility-first, fast layout and responsive design.
- **shadcn/ui**
  - Composable, headless components for tables, forms, dialogs, etc.

### 2.5 State & Data Fetching

- **Server-first approach**:
  - Server Components use Drizzle ORM (or Supabase client) for database queries
  - Types generated by MCP ensure type safety across the stack
- **Client-side data fetching**:
  - TanStack Query where necessary (highly interactive components only).
  - Client components use Supabase client with RLS policies for secure access.

## 5. Environment & Secrets

**MCP Configuration**: Managed through the MCP server setup (not via app environment variables).

**Runtime Database Access**: For Drizzle ORM and Supabase client queries:

- `NEXT_PUBLIC_SUPABASE_URL=...` (public, safe for client)
- `NEXT_PUBLIC_SUPABASE_ANON_KEY=...` (public, RLS-protected)
- `SUPABASE_SERVICE_ROLE_KEY=...` (server-only, for admin operations if needed)

**Architecture Split**:
- **MCP**: Schema migrations, type generation, admin tasks (development/ops)
- **Drizzle/Supabase client**: Runtime queries from Server Components and API routes (application code)

## 6. Non-Goals for v0

- No multi-tenant user management.
- No complex role-based permission system.
- No fully automated broker integrations yet (rely on CSV upload first).
